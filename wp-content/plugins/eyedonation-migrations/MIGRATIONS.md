There are no activation migrations. Preview stores only plugin-owned planning data. Each execution request applies at most one operation, or one 30-record search-index batch. Re-preview after a dependency completes to resolve its newly created IDs. Reports and history remain after plugin deactivation/uninstall.

Tracking uses nonautoloaded options: edm_history, edm_preview, edm_run_lock. This is a small fixed registry, so a dedicated table adds unnecessary schema maintenance. Checkpoints store destination IDs, before-images, fingerprints, actor/run IDs and times. Managed records use _edm_key, _edm_fingerprint and (template parts) _edm_source_sha256. Search uses independent eds_* keys and _eds_* metadata.

Lease acquisition uses atomic unique option insertion and compare-and-delete for expired leases/release. Workers verify token/expiry before and after operations. Completed checksums are immutable: package drift blocks preview. Completed migrations never reapply drift; prepare a new numbered migration. Initial release is still unreleased, so approved payload changes may be developed now, but changing a payload after executing it in a rehearsal requires a fresh isolated fixture. Preserve released payload/code unchanged in subsequent releases.

Adoption is explicit in approved.json: `adoptions[logical_key]` declares `destination_id` and `expected_content_sha256`. These are destination review mappings, not portable source IDs. Navigation adoption requires the exact declared slug/type. Part adoption patches the uniquely marked Navigation block in the existing content and preserves surrounding edits. Ambiguous identities or absent markers block.

No transactional rollback or automatic Undo is promised. Restore managed content using the administrator-only report's before-images, or restore a known-good complete backup while writes remain frozen. A new migration is required for drift repair after release.
