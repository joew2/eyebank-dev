# EyeDonation Site Migrations 0.1.0

Temporary deployment companion. Supports single-site WordPress 6.6+/PHP 8.1+, matching EyeDonation theme 0.1.0 and EyeDonation Search 0.1.0 for search steps. No content writes on activation or ordinary requests. Runtime navigation/news/search do not depend on this plugin.

Tools → Site Migrations exposes Preview Changes, Process Migrations, Resume / Retry and Download Report. Manage-options/target capabilities and nonces are checked. Batches require the administrator's backup acknowledgment and a current successful preview. The owner explicitly authorized this local preview with placeholder links. The payload records that authorization, resolves placeholder URLs through destination WordPress APIs and retains the existing homepage baseline. Replace final destinations before launch; production deployment is not authorized.

Registry, managed fields, dependencies, adoption, tracking, checksums, security/recovery and deployment details are in docs/MIGRATIONS.md, docs/HANDOFF.md and docs/DEPLOYMENT.md. Reports are administrator-only and include scoped before-images. Plugin-owned history remains after deactivation/uninstall. No automatic rollback, general database synchronization or production deployment is provided.

Test only in a separate isolated fixture: tests/integration.php requires an isolated bootstrap and refuses any table prefix except edrehearsal_. It creates synthetic public content and copies the supplied source images into fixture uploads. Never point it at production. The test additionally modifies only the copied fixture plugin payloads to exercise approved migrations. See docs/VERIFICATION.md for actual evidence and open gates.

Approved primary navigation update: all 22 labels and supplied destinations are included, with Give Now and More as non-link dropdown headings. Fresh installations use editable inline core Navigation blocks in the shipped header without needing a plugin or database seeding. Existing Site Editor overrides remain authoritative. Migration 008 explicitly updates only the managed primary wp_navigation record; classic menus/items/assignments, footer menu and homepage remain unchanged. Completed 001–007 payloads and checksums are preserved. The migration plugin may be deactivated after applying the menu. Edit the new menu in Appearance → Editor → Navigation; classic menus remain available through the legacy menus screen while transitioning. On a new site, the base navigation migrations can introduce their historical placeholder menu; run 008 afterward to apply the approved menu. No destination pages are created or overwritten.

Portable editable-homepage installer (010): on the destination site, activate the EyeDonation theme and migration plugin, upload the supplied homepage media, choose the target static page in Settings → Reading, then open Tools → Site Migrations → Install editable homepage — migration 010. Preview identifies the actual destination page and shows current/proposed content and editor flags. Acknowledge a recoverable backup and replacement, then Install / Resume. It inserts the complete theme pattern as native page content, assigns the editable homepage template, and disables that page’s legacy Thrive override when present while retaining stored builder content. No local page ID or original-content hash is required. No activation seeding occurs. The full legacy migration chain is not a prerequisite for 010. Existing front-page overrides must display Post Content, and all supplied media must resolve.

Preview changes no page content. Execution checks preview actor, freshness, resolved payload, homepage selection, and each field before writing. History retains before-images, actor/run IDs and per-field checkpoints. Retries after completion leave subsequent editorial changes intact. After application, deactivate the migration plugin if desired and use Edit Home Page for ordinary adjustments. Further page installers should receive their own numbered migration, template and editable-content pattern.
