# Process all updates

Open Tools → Site Migrations, check **I have a recoverable database backup and agree to process all site updates**, then click **Process all updates**. Keep the tab open until the completion/error summary appears. No separate Preview actions are required. Uploading, activating or opening the plugin does not run updates.

The coordinator runs 40 current tasks in order using short authenticated AJAX requests. It installs the editable homepage from bundled theme assets (including the latest hero/support crop), the converted pages, their later layout/media adjustments, member navigation, the current shared header/footer and a front-page template that displays native Post Content, then rebuilds search through batches. It retains existing search settings instead of importing development-specific mappings. Superseded homepage/menu installers and their old media preflight are not part of this job. It does not require the original support photograph in the Media Library.

Existing numbered installers prepare their plans internally immediately before execution, retaining their capability, prerequisite, conflict, backup, checksum and verification checks. Completed historical updates are skipped. The new homepage/shared-template steps keep durable before-images and reconcile partially written fields on retry. The shared-template step replaces saved EyeDonation header/footer overrides with the current theme designs; classic menus and unrelated theme overrides are not deleted.

Progress is saved in `edm_bulk_20261030_v1`. If the browser closes or a request fails, reopen the screen, check the agreement, and click the same button. Completed tasks are preserved. Missing prerequisite forms/plugins are reported by name; independent tasks continue. After correcting those prerequisites, the same button retries only unfinished tasks. A failed parent task prevents its dependent patch from modifying an unconverted page. This is a resumable deployment, not an all-or-nothing database transaction or automatic rollback.

Only an authenticated administrator with editing capabilities, a valid nonce and the explicit agreement can start/advance the job. A request lease prevents overlapping processors. Individual page installers still use their own execution leases. Opening the page performs no content writes. No live site updates are triggered by developing or packaging this plugin.

Requires the matching EyeDonation theme, the existing third-party form/View/file-manager definitions used by the converted pages, and EyeDonation Search. Uses the existing selected static homepage; if that is not configured, the job reports Settings → Reading as the action needed. Does not migrate the entire development database, users, submissions, newsletter PDFs or unrelated pages. Existing media and runtime plugins remain necessary for their dynamic features. After completion, clear site/CDN caches and review the site and forms. Site Migrations can then be deactivated.

Validation: PHP syntax; existing selected-page runner tests; new coordinator ordering/error/continuation/dependency/resume tests; before-image/interruption/conflict tests; current homepage payload generation with real WordPress block/HTML parsers and all bundled image files; actual admin-hook screen routing; browser tests with simulated AJAX verifying agreement, batches, errors, resume and desktop/mobile layout. These tests do not execute migrations against the online site or submit real forms.
