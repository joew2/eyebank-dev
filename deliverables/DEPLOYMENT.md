Do not deploy this preview to production. Required owner inputs and full live-copy rehearsal remain open.

1. Preserve this development installation; take a backup. Restore a recent live backup to a **separate** local/protected staging site. Disable outbound notifications and integrations there without carrying suppression settings to live.
2. Resolve the pending owner inputs in HANDOFF.md. Review all legacy theme business hooks before changing themes. Checksum differences require named approval in approved_asset_differences; never replace live files automatically. Files without attachments require a separately reviewed registration/import step.
4. Install matching theme, Search and Site Migrations ZIPs; activate the theme and plugins. Theme/migration activation does not seed content. Search activation only queues derived indexing.
5. Tools → Site Migrations → Preview Changes. Review actual environment, before/after values, media mappings and existing Site Editor overrides. The approved `eye-bank-home` path and unchanged baseline are packaged; verify the same identity/baseline on the destination. For search settings, inspect the destination baseline and declare its fingerprint; map term slugs/page paths locally. Preserve independent edits or resolve them explicitly.
6. Acknowledge a recoverable backup; Process each ready migration. Re-preview after dependencies complete. Closing a tab stops further browser batches; Resume / Retry reconciles saved checkpoints. A running state without a heartbeat after 90 seconds is marked interrupted. Download the administrator-only report.
7. Test navigation, existing inner pages, blog, registration/login and all transaction forms; latest three news posts and image/paragraph/permalink correspondence; search eligibility, filters, pagination, mobile and keyboard behavior. Verify no unresolved required placeholders, development domains or broken assets. Deactivate migrations and retest; deactivate Search separately to test native fallback.
8. Export intended Site Editor changes back to theme files or translate them into explicit migrations. Do not assume a theme ZIP includes page/menu database content. For file removals inspect template assignments and saved overrides first; remove obsolete files deliberately rather than merging ZIP contents indefinitely.

## Final UpdraftPlus cutover

Freeze all live writers **before** the final backup, including editors, registrations, scheduled writers and integrations. Maintenance mode alone is insufficient. Restore that final backup into the separate destination, install the tested releases, preview/process pending changes, verify, and export with UpdraftPlus. Migrate back to live using the owner's URL-handling workflow. Completion history travels with the database and is not bound to hostname. Check production URLs/configuration, media, forms, login, navigation, blog and search before reopening writes.

If cutover fails, restore the known-good complete backup while the freeze remains. After reopening writes, preserve new transactions; do not blindly overwrite them with an older backup. The plugin does not merge two active databases and does not provide transactional rollback.
